KIGUBI LIST — 审核流程（维护者文档） 本文件为纯文本说明。日常审核可在 GitHub Issues 中完成。 第一、首次配置 1. 在 GitHub 仓库中创建三个标签：submission、pending、approved。 2. 打开 data/config.js，确认： - backend 设为 "githubIssue" - githubIssueRepo 填成你的仓库路径，例如 moonfsunwe/Yuri-KIGUBI-list - githubIssueLabels 保持 ["submission", "pending"] 3. 提交推送后，数据提交页的按钮会自动启用。 第二、访客投稿 1. 访客打开 feedback.html，填写新增漫画或修改已有漫画。 - 新增漫画：需要标题、日文原名、几章，可填写别名、连载状况、作者。 - 章节色块：未知 → 有 → 无，相邻整数章节之间可插入 .5 特典章节。 - 修改漫画：搜索选择漫画后修改章节色块，可插入 .5 特典章节，必须写修改原因。 2. 点击「生成 GitHub Issue」后，会弹窗预览整理好的 Issue 内容。 3. 访客点击「前往 GitHub 提交 Issue」，在新 Issue 页面点击 Submit new issue。 4. 注意：访客需要拥有 GitHub 账号。 第三、审核投稿 1. 在 GitHub Issues 中查看带 submission / pending 标签的投稿。 2. 核对标题、日文原名、别名、章节状态、修改原因与变更对照。 3. 通过：把标签 pending 改成 approved，然后选择 Close issue。 4. 不通过：直接关闭 Issue 即可，无需改 approved。 第四、写入数据 1. 打开 data/manga-data.js，按现有结构插入记录。 2. slug 全站唯一，建议英文短横线。 3. 章节 order 支持小数，例如 5.5 表示第 5.5 话特典。 4. kiss / nudity 数组中的场景对象只写 characters 和 note，不要出现资源链接。 5. 可选字段：kissUnknown / nudityUnknown 可设为 true 或 1，表示该章节对应情况未知。 6. 可选字段 jpTitle 写日文原名，altTitles 写别名。 7. 推送部署后全站自动更新。 第五、Issue 标签维护 1. 新投稿默认标签：submission、pending。 2. 审核通过后：去掉 pending，加上 approved。 3. 如仓库标签颜色想统一，可以在 GitHub Issues 的 Labels 设置中调整：例如 submission 绿色、pending 橙色、approved 紫色。
